# Wonderful

Личный трекер задач: один вход, шесть корзин, недельный обзор. Синхронизация между
ноутбуком и телефоном, работа офлайн, данные в твоём Supabase.

> **Демо:** https://sergeitarasovdev.github.io/Wonderful/projects/wonderful/
> В этом репозитории приложение лежит в `projects/wonderful/` и открывается с витрины Wonderful Pages.
> Открывается пустым — базу подключаешь свою, см. «Быстрый старт».

---

## Что это

Не «ещё один to-do», а инструмент под конкретную проблему: в голове висит слишком много
незакрытых дел, и она перестаёт работать. Здесь всё выгружается в одно место, получает
решение, а заблокированное — дату пересмотра, чтобы перестать шуметь.

- **Один вход.** Всё пишется в «Входящие» одной строкой.
- **Пять решений.** Сейчас · Дальше · Ждёт · Когда-нибудь · Удалить.
- **Лимит трёх.** В «Сейчас» больше трёх задач не помещается — приложение не даст.
- **Дата пересмотра.** У всего, что ждёт денег, времени или чужого ответа.
- **Недельный обзор.** Четыре шага, двадцать минут.
- **Синхронизация.** Postgres в Supabase + Realtime + офлайн-очередь.

## Стек

| Слой | Чем |
|---|---|

| Авторизация | Supabase Auth, e-mail + пароль |

## Быстрый старт

### 1. Supabase

1. [supabase.com](https://supabase.com) → **New project** (бесплатного тарифа хватает).
2. **SQL Editor** → выполнить [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql).
3. **Authentication → Providers → Email** → выключить `Confirm email`.
4. **Project Settings → API** → скопировать `Project URL` и `anon public`.

### 2. Приложение

Открыть `index.html` (локально двойным щелчком или по адресу Pages), вставить URL и ключ,
нажать «Подключить», создать аккаунт и войти. Всё.

`anon public` — клиентский ключ, он и должен быть в браузере. **`service_role` не вставлять
никуда:** это мастер-ключ без ограничений.

## Деплой на GitHub Pages

1. Settings → Pages → Source: **Deploy from a branch** → `main` → `/ (root)` → Save.
2. Через минуту: `https://<логин>.github.io/Wonderful/`.

В корне лежит `.nojekyll` — он отключает обработку через Jekyll, иначе GitHub может
проигнорировать часть файлов. Не удалять.

Сайт публичный: любой, кто знает адрес, откроет интерфейс. Данные при этом не утекут —
ключей в файлах нет, а RLS отдаёт только строки владельца, то есть пустой список для всех
остальных. Если нужен закрытый доступ — Cloudflare Pages + Access вместо Pages.

## Как работает синхронизация

1. Изменение сразу применяется локально и уходит в Supabase.
2. Нет сети — операция ждёт в очереди. Состояние видно внизу слева:
   «синхронизировано», «офлайн · N в очереди», «ошибка» и кнопка «Сейчас».
3. Сверка с сервером при возврате на вкладку и при переключении окна.
4. Realtime-подписка подтягивает правки со второго устройства почти сразу.

Удаление «мягкое»: строка помечается `deleted`, чтобы удаление доехало до второго
устройства. Конфликт одной строки решается по `updated_at` — побеждает более поздняя правка.
Одновременная правка одного поля на двух устройствах не сливается: это сознательный
компромисс ради простоты.

## Модель данных

```
tasks(id, user_id, title, next_action, bucket, area_id, waiting_on,
      review_at, note, created_at, updated_at, done_at, deleted)
areas(id, user_id, name, sort, updated_at, deleted)
reviews(id, user_id, done_at, note, updated_at, deleted)
```

`bucket` ∈ `inbox | next | now | waiting | someday | done`.

Все имена латиницей, значения русские. Полные запросы удобнее писать в **Supabase → SQL
Editor**; в приложении есть раздел «Данные» с примерами и выгрузкой JSON/CSV.

Просроченные пересмотры:

```sql
select title, waiting_on, review_at, current_date - review_at as days_late
from tasks
where bucket = 'waiting' and review_at < current_date and not deleted
order by review_at;
```

## На чём основано

- **Getting Things Done** — доверенный список, следующее физическое действие, «когда-нибудь».
- **Personal Kanban** — лимит незавершённого: три слота вместо бесконечной доски.
- **Bullet Journal** — миграция: что не перенёс, то удаляешь.
- **super-productivity**, **Vikunja**, **Taskwarrior**, **tududi** — быстрый захват, свои
  данные, отсутствие обязательных полей, «сегодня» важнее архива.

Сознательно нет: тегов, вложенных проектов, повторяющихся правил, геймификации и дашбордов.
Каждое лишнее поле — повод не пользоваться системой.

## Обслуживание

Система живёт, пока обзор занимает двадцать минут. Если начинает требовать больше — она
перестала быть инструментом.

Раз в месяц — «Данные → Скачать JSON». Это бэкап на случай, если что-то пойдёт не так
с проектом Supabase.
